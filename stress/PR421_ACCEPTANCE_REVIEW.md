# PR421 验收指标复核

PR421 的 B0-B7 方案已经给出一组可量化目标。测试平台不能只复制阈值，
还必须固定样本口径，否则同一个指标可能因为超时样本、租户负载不均或
服务端指标缺失而得出错误结论。

## 指标口径

| PR421 指标 | 原目标 | 测试平台执行口径 | 复核结论 |
| --- | --- | --- | --- |
| Search P95 隔离度 | 突发前后 `≤1.2x` | 只比较同 profile、同租户、同查询集合的成功请求 P95；超时率另行判定 | 合理，但不能把超时请求混入服务延迟 |
| Jain 公平指数 | `≥0.9` | 至少 2 个独立租户、相同目标负载；使用完成吞吐，不使用发送量 | 合理；单租户必须 `INCONCLUSIVE` |
| 拒绝正确性 | `503/429 + Retry-After + reason_code` | 逐个拒绝响应检查状态码、Retry-After、reason_code，并记录实际返回耗时 | 合理；“100%”必须指字段完整率 |
| Commit 成功保证 | 崩溃后恢复率 `100%` | 只统计已返回 202 的任务；经过 drain/最终状态查询后计算完成率 | 合理；轮询窗口超时不能算成功 |
| 级联抑制 | `deadline_exhausted = 0` | 同时比较故障租户与旁观租户的 Search P95、错误率和降级标记 | 原指标偏严，单个慢引擎可能允许局部 deadline 超时；应以跨租户影响为主 |
| 规格联动 | 四档逐档通过 | 每档记录 profile、资源限制、并发、吞吐、P95、错误率和 RSS 峰值 | 合理；不能只改环境变量却不记录实际生效 profile |
| 饱和入口 | 128 并发，Search 拒绝率 `<5%`，被拒 `<1s` | 记录到达并发、入口拒绝、车道拒绝、Search 超时率和返回耗时 | 不足；还需检查拒绝后恢复和队列是否持续增长 |
| L5 公平 | 热租户 200 commit，其他租户各 20，后者中位延迟 `≤1.5x` | 使用相同消息大小和相同 profile，分别统计每租户完成率、P50/P95 和最大连续等待 | 合理；应增加 commit 未完成率和最长等待上限 |

formal suite 已增加 `saturation`（128 并发）和 `tenant-skew`
（200/20/20/20 显式 Commit 分布）两个场景，并由
`stress/echomem/acceptance.py` 对可测指标执行逐项判定。它们验证的是负载
输入和黑盒结果；如果 EchoMem 未暴露入口拒绝原因、Retry-After、车道指标
或服务端执行时间，相关服务端门禁仍为 `INCONCLUSIVE`。

## 需要补充的统一口径

1. **成功请求与整体请求分离**：P50/P95/P99 同时输出成功请求延迟、
   全部请求端到端延迟、超时率和 HTTP 错误率。
2. **最终状态必须排空**：测试窗口结束后继续查询已接受 Commit，直到全部
   进入终态或达到明确的 drain deadline；未知终态单独列出。
3. **指标覆盖率单独判定**：没有 lane 四元组、request_id、服务端开始时间
   或终态字段时，输出 `INCONCLUSIVE`，不能用客户端时间补齐。
4. **公平性需要负载条件**：同一租户数不足两个、目标负载不相等或成功样本
   不足时，不计算或不展示 PASS。
5. **资源指标需要原始证据**：CPU counter 必须至少有两个有效采样点并完成
   单位换算核对；RSS 必须在相同冷却状态下比较。

## 当前 PR28 对齐情况

测试平台已经把 PR421 的目标写入 `formal_suite.py` 的 `suite.json`，
并生成 `acceptance.json` 和无密钥的 `model_analysis_input.json`，同时采集
B7 lane/fan-out 指标族及其有界标签。当前仍需 EchoMem 或部署环境
提供以下能力，平台才能执行完整门禁：

- cursor/消息集合导出，用于 Commit 持久化对账；
- 受控进程/依赖重启，用于 kill-9 和恢复场景；
- 可控慢引擎/LLM 故障，用于熔断和级联抑制；
- profile 资源限制和实际生效配置，用于四档容量阶梯；
- 取消/断连后的后台任务和资源回收观测。

因此报告应把“目标已配置”与“目标已验证”分开显示。任一可测门禁失败
才判 `FAIL`；证据不足或能力未实现判 `INCONCLUSIVE`，只有所有门禁均有
充分证据且通过时才允许 `PASS`。模型分析只能基于结构化证据，不能把
`INCONCLUSIVE` 推断成通过。
