# 动态评测参数归属设计意图

## 核心原则

动态评测的 `run_eval.py` **只定义三类参数**：

1. **模式选择与数据集参数** - `--dataset`、`--sample`、`--questions`（指定 dataset 进入 replay 模式，否则 generate 模式）
2. **评测器与场景生成参数** - `--evaluator-config`、`--user-simulator-config`、`--scenario-model`/`--scenario-base-url`/`--scenario-api-key`、`--num-memories`/`--num-queries` 等 generate 模式参数
3. **评测基础设施参数** - `--concurrency`、`--out-dir`、`--check`、`--allow-diagnostics`（通过 `add_eval_args()` 声明）

所有其他参数（LLM 凭据、记忆后端连接、commit 超时、插件特有配置）
**完全委托给插件和记忆后端定义**，不由 dynamic `run_eval` 直接声明。

> 设计原则与 benchmark 评测一致，详见 `benchmarks/doc/设计意图.md`。

## 参数声明链路

```
dynamic run_eval build_parser()
  │
  ├── 模式选择参数 (dynamic 自己定义)
  ├── 评测器配置 (dynamic 自己定义)
  ├── Generate 模式参数 (dynamic 自己定义)
  ├── 场景生成 LLM (dynamic 自己定义, 仅 generate 模式)
  ├── add_eval_args(parser)            ← --concurrency / --out-dir / --check / --allow-diagnostics
  │
  └── add_agent_plugin_args(parser)    ← 预解析 --agent-plugin，调用所选插件的 add_arguments()
        │
        插件 add_arguments():
          ├── add_llm_args(parser)           ← LLM 凭据/参数 (shared helper)
          ├── add_qa_args(parser)            ← QA 检索行为参数 (shared helper, bare_llm 调用)
          ├── add_memory_backend_args(parser) ← 后端连接 + commit 超时 (backends/memory_args.py)
          └── 插件自身参数                    ← 如 --echoagent-url, --username, --password 等
```

## 参数分类

| 参数类别 | 声明者 | 声明位置 | 示例 |
|---------|--------|---------|------|
| 模式选择 | dynamic | `dynamic/run_eval.py` | `--dataset`, `--sample`, `--questions` |
| 评测器配置 | dynamic | `dynamic/run_eval.py` | `--evaluator-config`, `--user-simulator-config` |
| Generate 模式 | dynamic | `dynamic/run_eval.py` | `--num-memories`, `--num-queries`, `--typing-speed-ms` |
| 场景生成 LLM | dynamic | `dynamic/run_eval.py` | `--scenario-model`, `--scenario-base-url`, `--scenario-api-key` |
| 评测基础设施 | dynamic | `shared/eval_base.py` -> `add_eval_args()` | `--concurrency`, `--out-dir`, `--check`, `--allow-diagnostics` |
| LLM 凭据 | 插件 | `shared/eval_base.py` -> `add_llm_args()` | `--llm-base-url`, `--llm-model`, `--llm-api-key` |
| 后端连接 | 记忆后端 | `backends/memory_args.py` -> `add_memory_backend_args()` | `--echomem-url`, `--account`, `--echomem-auth-key` |
| 后端行为 | 记忆后端 | `backends/memory_args.py` -> `add_memory_backend_args()` | `--commit-timeout-s`, `--commit-poll-interval-s` |
| 插件特有 | 插件 | `plugins/*/plugin.py` -> `add_arguments()` | `--echoagent-url`, `--username`, `--password` |

## 与 benchmark 评测的差异

| 方面 | benchmark | dynamic |
|------|-----------|---------|
| 默认插件 | `bare_llm` | `echo_agent` |
| QA 参数 | 插件通过 `add_qa_args()` 声明 | `echo_agent` 不声明 QA 参数（走 EchoAgent 管线）；`bare_llm` 声明 |
| 场景生成 | 无 | `--scenario-*` 三参数 + `--num-memories`/`--num-queries` 等 |
| Judge 参数 | `--judge-model` 等 | 无独立 Judge；质量评估用 `--llm-*` 参数 |
| 评测器配置 | 无 | `--evaluator-config` YAML（维度 + prompt 模板）|

## echo_agent 与 LLM 参数

`echo_agent` 插件调用 `add_llm_args()` 声明 `--llm-*` 参数，不是因为插件自身用 LLM
做 QA（它走 EchoAgent 管线），而是因为动态评测框架需要 `--llm-*` 参数做质量评估。
让插件声明可避免切换到 `vikingbot`/`bare_llm`（它们也声明 `--llm-*`）时出现
argparse 重复声明冲突。

## 委托机制

`add_agent_plugin_args(parser)` 在 `shared/eval_base.py` 中实现：

1. 预解析 `sys.argv` 找到 `--agent-plugin` 的值（默认 `echo_agent`）
2. 通过 `plugins.get_plugin_class(plugin_name)` 获取插件类
3. 调用 `plugin_cls.add_arguments(parser)` - 插件在此时声明自己需要的所有参数

`validate_dynamic_args()` 使用 `getattr(args, ..., default)` 读取参数值，
不关心参数是由谁声明的。即使某个插件没有声明某个参数（如 `echo_agent` 不声明
QA 参数），`getattr` 会使用默认值，不会报错。

## 场景生成 LLM 与质量评估 LLM

dynamic 有两组 LLM 参数：

- **场景生成 LLM** (`--scenario-*`): 用于 generate 模式生成背景记忆和查询。由
  `run_eval` 自身声明，因为场景生成是动态评测特有逻辑，不属于插件。
- **质量评估 LLM** (`--llm-*`): 用于评估回复质量。由插件通过 `add_llm_args()`
  声明，因为不同插件都需要 LLM 做质量评估，委托给插件声明避免重复。

`--scenario-base-url`/`--scenario-api-key` 与 `--llm-base-url`/`--llm-api-key`
互补：一个有值另一个为空时，空的自动复制有值的。
