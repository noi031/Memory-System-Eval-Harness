# Benchmark 评测参数归属设计意图

## 核心原则

Benchmark 评测的 `run_eval.py` **只定义三类参数**：

1. **数据集参数** — `--dataset`、`--sample`、`--questions`、`--question-ids` 等
2. **Judge 参数** — `--judge-model`、`--judge-api-key`、`--judge-base-url` 等
3. **评测基础设施参数** — `--concurrency`、`--out-dir`、`--allow-incomplete-imports`

所有其他参数（LLM 凭据、QA 检索行为、记忆后端连接、commit 超时、插件特有配置）
**完全委托给插件和记忆后端定义**，不由 benchmark `run_eval` 直接声明。

## 参数声明链路

```
benchmark run_eval build_parser()
  │
  ├── dataset 参数 (benchmark 自己定义)
  ├── judge 参数 (benchmark 自己定义)
  ├── add_eval_args(parser)            ← 仅 --concurrency / --out-dir / --allow-incomplete-imports
  │
  └── add_agent_plugin_args(parser)    ← 预解析 --agent-plugin，调用所选插件的 add_arguments()
        │
        插件 add_arguments():
          ├── add_llm_args(parser)           ← LLM 凭据/参数 (shared helper)
          ├── add_qa_args(parser)            ← QA 检索行为参数 (shared helper)
          ├── add_memory_backend_args(parser) ← 后端连接 + commit 超时 (backends/memory_args.py)
          └── 插件自身参数                    ← 如 --mcp-url, --tool-calling, --vikingbot-workspace 等
```

## 参数分类

| 参数类别 | 声明者 | 声明位置 | 示例 |
|---------|--------|---------|------|
| 数据集 | benchmark | `benchmarks/*/run_eval.py` | `--dataset`, `--sample`, `--questions` |
| Judge | benchmark | `benchmarks/*/run_eval.py` | `--judge-model`, `--judge-base-url` |
| 评测基础设施 | benchmark | `shared/eval_base.py` → `add_eval_args()` | `--concurrency`, `--out-dir` |
| LLM 凭据 | 插件 | `shared/eval_base.py` → `add_llm_args()` | `--llm-base-url`, `--llm-model`, `--llm-api-key` |
| QA 行为 | 插件 | `shared/eval_base.py` → `add_qa_args()` | `--top-k`, `--memory-budget-chars`, `--question-timeout-s` |
| 后端连接 | 记忆后端 | `backends/memory_args.py` → `add_memory_backend_args()` | `--echomem-url`, `--account`, `--echomem-auth-key` |
| 后端行为 | 记忆后端 | `backends/memory_args.py` → `add_memory_backend_args()` | `--commit-timeout-s`, `--commit-poll-interval-s` |
| 插件特有 | 插件 | `plugins/*/plugin.py` → `add_arguments()` | `--mcp-url`, `--tool-calling`, `--vikingbot-workspace` |

## 委托机制

`add_agent_plugin_args(parser)` 在 `shared/eval_base.py` 中实现：

1. 预解析 `sys.argv` 找到 `--agent-plugin` 的值（默认 `bare_llm`）
2. 通过 `plugins.get_plugin_class(plugin_name)` 获取插件类
3. 调用 `plugin_cls.add_arguments(parser)` — 插件在此时声明自己需要的所有参数

插件在 `add_arguments()` 中调用共享 helper：
- `add_llm_args(parser)` — 声明 `--llm-base-url` 等 7 个 LLM 参数
- `add_qa_args(parser)` — 声明 `--top-k`、`--memory-budget-chars`、`--question-timeout-s`
- `add_memory_backend_args(parser)` — 声明后端连接参数和 commit 超时参数

## EvalConfig 的角色

`EvalConfig` 是一个纯数据类，存储从 argparse namespace 提取的配置值。
`build_config_from_args(args)` 使用 `getattr` 从 namespace 中读取值，
不关心每个参数是由谁声明的。即使某个插件没有声明某个参数（如 `echo_agent`
在动态评测中不声明 QA 参数），`getattr` 会使用默认值，不会报错。

benchmark 的 `import_memory` 模块、`qa` 模块和 `judge` 模块从 `EvalConfig`
读取这些值（如 `config.commit_timeout_s`、`config.top_k`），无需关心参数的
声明来源。

## 多插件多后端架构

每个插件可以定义自己的记忆后端。当前实现中：
- `echomem_mcp` 插件使用 EchoMem 后端
- `openviking_mcp` 插件使用 OpenViking 后端
- `vikingbot` 和 `echo_agent` 插件支持 `--memory-backend` 选择 echomem 或 openviking

后端连接参数通过 `add_memory_backend_args()` 统一声明，不同后端共享同一组
CLI flag 名称（如 `--echomem-url` 同时用于 EchoMem 和 OpenViking 的地址）。
插件通过自己的 `add_arguments()` 调用 `add_memory_backend_args()` 将后端参数
暴露给 benchmark `run_eval`。
