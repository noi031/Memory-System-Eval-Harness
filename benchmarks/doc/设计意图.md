# Benchmark 评测参数归属设计意图

## 核心原则

Benchmark 评测的 `run_eval.py` **只定义三类参数**：

1. **数据集参数** — `--dataset`、`--sample`、`--questions`、`--question-ids` 等
2. **Judge 参数** — `--judge-model`、`--judge-api-key`、`--judge-base-url` 等
3. **评测基础设施参数** — `--concurrency`、`--out-dir`、`--check`、`--allow-diagnostics`

所有其他参数（LLM 凭据、QA 检索行为、记忆后端连接、commit 超时、插件特有配置）
**完全委托给插件和记忆后端定义**，不由 benchmark `run_eval` 直接声明。

## 参数声明链路

```
benchmark run_eval build_parser()
  │
  ├── dataset 参数 (benchmark 自己定义)
  ├── judge 参数 (benchmark 调用 add_judge_args + 可选本地扩展)
  ├── add_eval_args(parser)            ← --concurrency / --out-dir / --check / --allow-diagnostics
  ├── add_judge_args(parser)           ← --judge-model / --judge-api-key / --judge-base-url
  │
  └── add_agent_plugin_args(parser)    ← 预解析 --agent-plugin，调用所选插件的 add_arguments()
        │
        插件 add_arguments():
          ├── add_llm_args(parser)           ← LLM 凭据/参数 (shared helper)
          ├── add_qa_args(parser)            ← QA 检索行为参数 (shared helper)
          ├── add_memory_backend_args(parser) ← 后端连接 + commit 超时 (backends/memory_args.py)
          └── 插件自身参数                    ← 如 --mcp-url, --tool-calling, --vikingbot-workspace 等
```

## 参数分类

| 参数类别 | 声明者 | 声明位置 | 示例 |
|---------|--------|---------|------|
| 数据集 | benchmark | `benchmarks/*/run_eval.py` | `--dataset`, `--sample`, `--questions` |
| Judge | benchmark | `shared/eval_base.py` -> `add_judge_args()` | `--judge-model`, `--judge-base-url` |
| 评测基础设施 | benchmark | `shared/eval_base.py` → `add_eval_args()` | `--concurrency`, `--out-dir`, `--check`, `--allow-diagnostics` |
| LLM 凭据 | 插件 | `shared/eval_base.py` → `add_llm_args()` | `--llm-base-url`, `--llm-model`, `--llm-api-key` |
| QA 行为 | 插件 | `shared/eval_base.py` → `add_qa_args()` | `--top-k`, `--memory-budget-chars`, `--question-timeout-s` |
| 后端连接与行为 | 记忆后端 | `backends/memory_args.py` → `add_memory_backend_args()` | 由各插件按需声明，见下文各插件章节 |
| 插件特有 | 插件 | `plugins/*/plugin.py` → `add_arguments()` | `--mcp-url`, `--tool-calling`, `--vikingbot-workspace` |

## 委托机制

`add_agent_plugin_args(parser)` 在 `shared/eval_base.py` 中实现：

1. 预解析 `sys.argv` 找到 `--agent-plugin` 的值（默认 `bare_llm`）
2. 通过 `plugins.get_plugin_class(plugin_name)` 获取插件类
3. 调用 `plugin_cls.add_arguments(parser)` — 插件在此时声明自己需要的所有参数

插件在 `add_arguments()` 中调用共享 helper：
- `add_llm_args(parser)` — 声明 `--llm-base-url` 等 7 个 LLM 参数
- `add_qa_args(parser)` — 声明 `--top-k`、`--memory-budget-chars`、`--question-timeout-s`
- `add_memory_backend_args(parser)` — 声明后端连接参数和 commit 超时参数

## EvalConfig 的角色

`EvalConfig` 是一个纯数据类，存储从 argparse namespace 提取的配置值。
`build_config_from_args(args)` 使用 `getattr` 从 namespace 中读取值，
不关心每个参数是由谁声明的。即使某个插件没有声明某个参数（如 `echo_agent`
在动态评测中不声明 QA 参数），`getattr` 会使用默认值，不会报错。

benchmark 的 `import_memory` 模块、`qa` 模块和 `judge` 模块从 `EvalConfig`
读取这些值（如 `config.commit_timeout_s`、`config.top_k`），无需关心参数的
声明来源。

## 各插件的记忆后端参数

记忆后端参数通过 `backends/memory_args.py` 的 `add_memory_backend_args()` 声明。
各插件在 `add_arguments()` 中按需调用，通过 `with_backend_choice` 参数控制是否
暴露 `--memory-backend` 选择项。不同后端（EchoMem、OpenViking）共享同一组 CLI
flag 名称（如 `--echomem-url` 同时用于两个后端的地址），使用 OpenViking 时需
显式指定 `--echomem-url http://127.0.0.1:19080`。

插件间参数重复声明是正常的——插件间进程隔离，各自独立声明，不共享代码。

### bare_llm 插件

不调用 `add_memory_backend_args()`，不声明任何记忆后端参数。适用于无记忆
系统基线测试。

### echomem_mcp 插件

调用 `add_memory_backend_args(parser, with_backend_choice=False)`，固定使用
EchoMem 后端，不暴露 `--memory-backend`。

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--echomem-url` | `http://127.0.0.1:8010` | EchoMem HTTP 地址 |
| `--echomem-auth-key` | (空) | X-Auth-Key（也可通过 `ECHOMEM_AUTH_KEY` 设置） |
| `--account` | `default` | 后端 account |
| `--user-id` | `default` | 后端 user_id |
| `--agent-id` | `default` | 后端 agent_id |
| `--workspace` | (空) | 后端 workspace 路径 |
| `--commit-timeout-s` | `0` | Commit 轮询超时（秒），0 表示无限等待 |
| `--commit-poll-interval-s` | `2.0` | Commit 轮询间隔（秒） |
| `--timeout-s` | `60.0` | 后端 HTTP 请求超时（秒） |
| `--max-retries` | `3` | 后端 HTTP 请求最大重试次数 |

### openviking_mcp 插件

调用 `add_memory_backend_args(parser, with_backend_choice=False)`，固定使用
OpenViking 后端，不暴露 `--memory-backend`。使用时需指定
`--echomem-url http://127.0.0.1:19080`。

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--echomem-url` | `http://127.0.0.1:8010` | OpenViking HTTP 地址（实际使用时需改为 19080 端口） |
| `--echomem-auth-key` | (空) | 后端 API Key |
| `--account` | `default` | 后端 account |
| `--user-id` | `default` | 后端 user_id |
| `--agent-id` | `default` | 后端 agent_id |
| `--workspace` | (空) | 后端 workspace 路径 |
| `--commit-timeout-s` | `0` | Commit 轮询超时（秒），0 表示无限等待 |
| `--commit-poll-interval-s` | `2.0` | Commit 轮询间隔（秒） |
| `--timeout-s` | `60.0` | 后端 HTTP 请求超时（秒） |
| `--max-retries` | `3` | 后端 HTTP 请求最大重试次数 |

### vikingbot 插件

调用 `add_memory_backend_args(parser, with_backend_choice=True)`，支持通过
`--memory-backend` 选择 echomem 或 openviking 后端。选择 openviking 时需指定
`--echomem-url http://127.0.0.1:19080`。

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--memory-backend` | `echomem` | 记忆后端选择：`echomem` 或 `openviking` |
| `--echomem-url` | `http://127.0.0.1:8010` | 后端 HTTP 地址 |
| `--echomem-auth-key` | (空) | 后端 X-Auth-Key |
| `--account` | `default` | 后端 account |
| `--user-id` | `default` | 后端 user_id |
| `--agent-id` | `default` | 后端 agent_id |
| `--workspace` | (空) | 后端 workspace 路径 |
| `--commit-timeout-s` | `0` | Commit 轮询超时（秒），0 表示无限等待 |
| `--commit-poll-interval-s` | `2.0` | Commit 轮询间隔（秒） |
| `--timeout-s` | `60.0` | 后端 HTTP 请求超时（秒） |
| `--max-retries` | `3` | 后端 HTTP 请求最大重试次数 |

### echo_agent 插件

调用 `add_memory_backend_args(parser, with_backend_choice=True)`，支持通过
`--memory-backend` 选择 echomem 或 openviking 后端。主要用于动态评测。
`--echomem-auth-key` 留空时自动从 echoagent 插件解析；`--agent-id` 为 `default`
时自动设为 `echoagent`。选择 openviking 时需指定
`--echomem-url http://127.0.0.1:19080`。

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--memory-backend` | `echomem` | 记忆后端选择：`echomem` 或 `openviking` |
| `--echomem-url` | `http://127.0.0.1:8010` | 后端 HTTP 地址 |
| `--echomem-auth-key` | (空) | 后端 X-Auth-Key（留空时自动从 echoagent 插件解析） |
| `--account` | `default` | 后端 account |
| `--user-id` | `default` | 后端 user_id |
| `--agent-id` | `default` | 后端 agent_id（为 `default` 时自动设为 `echoagent`） |
| `--workspace` | (空) | 后端 workspace 路径 |
| `--commit-timeout-s` | `0` | Commit 轮询超时（秒），0 表示无限等待 |
| `--commit-poll-interval-s` | `2.0` | Commit 轮询间隔（秒） |
| `--timeout-s` | `60.0` | 后端 HTTP 请求超时（秒） |
| `--max-retries` | `3` | 后端 HTTP 请求最大重试次数 |
