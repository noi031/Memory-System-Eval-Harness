# EchoMemClient 设计意图

## 定位

`EchoMemClient` 是 EchoMem 记忆后端的 HTTP 客户端，负责 session 生命周期管理、记忆注入、commit 轮询和检索。它继承 `BaseHTTPMemoryClient`，仅用标准库 `urllib`，零第三方依赖。

## 为什么放在 backends/ 而不是 plugin 目录

多个 plugin 会调用同一个记忆后端：`echomem_mcp` 通过 MCP 协议检索 EchoMem 记忆，`vikingbot` 和 `echo_agent` 通过 REST API 注入记忆并创建会话。把客户端放在共享的 `backends/echomem/` 目录下，所有 plugin 统一从这里 import，避免代码重复。

## 核心设计

### 身份隔离

评测运行时，每个 run 创建独立的 tenant/user/key 三元组，避免不同评测之间的数据污染：

- `provision_isolated_identity(label)` -- 调用 `/api/auth/tenants` 创建 tenant，再创建 user 和 auth key，然后把 client 切换到新身份
- `delete_current_identity()` -- 调用 `/api/auth/account/delete` 删除 tenant
- `cleanup_pending_identities()` -- 模块级函数，通过 `atexit` 注册，进程退出时自动清理所有临时身份

`--reuse-memory-account` 跳过身份隔离，直接用 CLI 传入的 account/user/agent；`--keep-memory-account` 保留临时身份用于诊断（不执行 atexit 清理）。

### Commit 轮询

EchoMem 的 commit 是异步的：`commit_session()` 返回 `archive_id`，然后需要轮询状态直到 completed/failed。轮询逻辑在基类 `BaseHTTPMemoryClient.poll_commit()` 中实现（模板方法模式），子类只需覆盖：

- `_fetch_commit_status(session_id, archive_id)` -- GET `/api/sessions/{sid}/commits/{aid}`
- `_parse_commit_status(resp)` -- 处理 EchoMem 的嵌套 status dict 格式（`resp["status"]` 可能是 `{"status": "completed"}` 而非纯字符串）
- `_extract_commit_error(resp, status)` -- 从嵌套 dict 中提取错误信息

### Session 生命周期

```
open_session(title) -> session_id
  -> add_message(session_id, role, content) * N
  -> commit_session(session_id) -> archive_id
  -> poll_commit(session_id, archive_id) -> CommitResult
```

`open_session` 构造的 body 包含 `agent_id`、`metadata`（title/account_id/user_id）和可选的 `workspace`。`add_message` 支持 `created_at` 和 `role_id` 用于时间线回放。

### 检索

四个检索方法对应 EchoMem 的 HTTP 端点：

| 方法 | 端点 | 说明 |
|---|---|---|
| `search(query, top_k)` | POST `/api/retrieval/search` | 语义检索，返回 `SearchResult` 列表 |
| `fs_read(uri)` | GET `/fs/read?uri=` | 读取单个 URI 的完整内容 |
| `fs_list(uri, recursive)` | GET `/fs/ls?uri=` | 列出 URI 前缀下的条目 |
| `fs_glob(pattern)` | POST `/fs/glob` | 按 glob 模式查找条目 |

`search` 的 response 可能是 `{"result": {"items": [...]}}` 或 `{"items": [...]}` 两种格式，client 做了兼容处理。
