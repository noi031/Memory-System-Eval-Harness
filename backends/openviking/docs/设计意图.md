# OpenVikingClient 设计意图

## 定位

`OpenVikingClient` 是 OpenViking 记忆后端的 HTTP 客户端，负责 session 生命周期管理、记忆注入、commit 轮询和检索。它继承 `BaseHTTPMemoryClient`，仅用标准库 `urllib`，零第三方依赖。

## 为什么放在 backends/ 而不是 plugin 目录

与 EchoMemClient 同理：多个 plugin 会调用同一个记忆后端。`openviking_mcp` 通过 MemoryClient 协议检索 OpenViking 记忆，`vikingbot` 和 `echo_agent` 通过 REST API 注入记忆并创建会话。把客户端放在共享的 `backends/openviking/` 目录下，所有 plugin 统一从这里 import。

## 核心设计

### 身份隔离

OpenViking 没有服务端 tenant 管理接口，身份隔离通过生成唯一的 account 名称实现：

- `provision_isolated_identity(label)` -- 生成 `eval-{label}-{uuid_hex}` 格式的 account 名，设置到 `self.account`，后续所有请求的 `X-OpenViking-Account` header 携带此值
- `delete_current_identity()` -- 无操作（OpenViking 数据持久化在 workspace 中，没有服务端删除接口）

身份隔离依赖 OpenViking 服务端按 account header 区分数据的作用域，而非像 EchoMem 那样创建真实的 tenant。

### Commit 轮询

OpenViking 的 commit 也是异步的，但返回的是 `task_id` 而非 `archive_id`。轮询逻辑复用基类 `BaseHTTPMemoryClient.poll_commit()`，子类覆盖：

- `_fetch_commit_status(session_id, archive_id)` -- GET `/api/v1/tasks/{task_id}`
- `_commit_failed_statuses()` -- 额外包含 `"cancelled"` 和 `"canceled"` 两种拼写

### Session 生命周期

```
open_session(title) -> session_id
  -> add_message(session_id, role, content) * N
  -> commit_session(session_id) -> task_id
  -> poll_commit(session_id, task_id) -> CommitResult
```

`open_session` 在客户端生成 session_id（`eval-{safe_title}-{uuid_hex}`），POST 到服务端创建。`add_message` 将 content 包装为 `parts: [{"type": "text", "text": content}]` 格式，role 归一化为 `user` / `assistant`。

### 双域检索

OpenViking 的记忆分为 user scope 和 agent scope，`search()` 同时检索两个域并合并去重：

```
search(query, top_k)
  -> _search_once(query, "viking://user/memories/", top_k)  # user scope
  -> _search_once(query, "viking://agent/memories/", top_k) # agent scope
  -> merge + dedup by URI + sort by score + truncate to top_k
```

`_search_once` 的 response 格式多样（可能是 list、dict with items/results/hits/memories/resources），client 做了全面的兼容处理。特别地，当 response 同时包含 `memories` 和 `resources` 两个 list 时，合并两者。

### 本地文件系统 fs 操作

与 EchoMemClient 不同，OpenViking 没有暴露 HTTP `/fs/read`、`/fs/list`、`/fs/glob` 端点。记忆文件存储在本地 workspace 文件系统中，路径映射规则：

```
viking://user/memories/foo.md
  -> {workspace}/viking/{account}/user/memories/foo.md
```

| 方法 | 实现 |
|---|---|
| `fs_read(uri)` | `_uri_to_local_path(uri)` -> `path.read_text()` |
| `fs_list(uri, recursive)` | 遍历本地目录，`_local_to_uri(child)` 构建返回 URI |
| `fs_glob(pattern)` | `account_root.glob(rel)` 匹配本地文件 |

`recursive=True` 时 `fs_list` 委托给 `fs_glob` 处理 `**` 通配符。

## 与 EchoMemClient 的对比

| 维度 | EchoMemClient | OpenVikingClient |
|------|---------------|-------------------|
| 服务端口 | 8010 | 19080 |
| 身份隔离 | 服务端创建 tenant/user/key | 客户端生成唯一 account 名 |
| 身份清理 | atexit 删除 tenant | 无操作 |
| Commit 返回 | archive_id | task_id |
| Commit 失败状态 | failed, error | failed, error, cancelled, canceled |
| Search 域 | 单域 | 双域（user + agent）合并去重 |
| fs 操作 | HTTP 端点 | 本地文件系统 |
| Session ID | 服务端生成 | 客户端生成 |
